3. **Как на этом заработать?**

Техническая часть сильная: монорепо, Next.js 16 + NestJS + Prisma + PostgreSQL, три языка, mastery, граф пререквизитов, рекомендации, тесты. Слабым был продуктовый слой. Цель этой доработки: **каждый из четырёх ответов показывается в продукте вживую, а не только на словах.**

Защиту перенесли на **понедельник, 2 ноября 2026**. Владелец **одобрил расширение рамок MVP** функциями из этого брифа. Это одобрение **рамок**, а не всего подряд. ## 2. Функции

Каждой функции дай стабильный ID требования в `requirements.md` (новые префиксы ниже) с критериями приёмки. Приоритеты: **Must** (не режем), **Should**, **Could** (режем первыми).

### A. Доказательство обучения (ответ на вопрос 2)

#### A1. Входной и итоговый тест + отчёт «Твой рост» (FR-GROW, Must)
- **Входной (диагностический) тест** по предмету: по 3 вопроса на каждую из 6 тем (18 вопросов). Проходится **без регистрации** (автоматически стартует гостевой режим, ADR-0006) примерно за 5 минут. Это же **бесплатный инструмент-вход** из C2.
- **Итоговый тест**: та же структура, но **параллельная форма**, то есть другие вопросы того же уровня, чтобы рост нельзя было объяснить запоминанием ответов. Доступен после того, как ученик поработал с темами (например, ≥ 4 темы не `NOT_STARTED`; порог обоснуй).
- Оба теста обновляют mastery по правилам ADR-0004 (последняя попытка, включившая тему). Входной тест сразу даёт осмысленную карту знаний.
- **Отчёт «Твой рост»**: общий балл «было → стало», дельта по каждой теме, какие темы перешли в `MASTERED`. Простая визуализация (столбики до/после), без новых библиотек графиков, если без них можно обойтись.
- Модель данных: предложи сам. Например, новые значения `QuizKind` (`DIAGNOSTIC`, `FINAL`) или отдельное поле роли у квиза. Объясни выбор в ADR.
- Контент: 36 новых вопросов (18 + 18) на tg/ru/en с объяснениями. Это самый большой контентный трек, начинай его сразу (skill `add-lesson-content`, `seed:check`).

#### A2. Практика с автопроверкой (FR-PRAC, Must; запуск кода в браузере: Could)
- Новый тип вопроса **`SHORT_ANSWER`**: ученик сам вводит ответ («Что выведет этот код?», «Сколько раз выполнится цикл?», «Какое значение будет у `x`?»). Проверка **на сервере**: нормализация (trim, регистр, лишние пробелы, при необходимости числа) против списка допустимых ответов. Правильные ответы **никогда** не уходят клиенту до отправки (как FR-QUIZ-06).
- **Блок «Практика»** у каждой темы: 3 задачи с автопроверкой и объяснением. Короткие ответы можно добавить и в квизы тем.
- Расширь `seed:check`: у каждого `SHORT_ANSWER` есть хотя бы один допустимый ответ во всех нужных формах, и он не пустой.
- **Could:** задачи «напиши код» с запуском Python в браузере (Pyodide в Web Worker) и сравнением stdout с ожидаемым. Это новая внешняя зависимость и большой бандл, поэтому только с отдельного одобрения владельца. Если делаешь, честно отметь, что проверка идёт на клиенте и в mastery не засчитывается.

#### A3. Интервальное повторение 1 → 3 → 7 дней (FR-REVIEW, Must)
- Когда тема становится `MASTERED`, назначается повторение через **1 день**. Успешное повторение (≥ 80%) даёт следующий интервал **3 дня**, потом **7 дней**, потом 21 день (последний шаг обоснуй). Провал: статус темы понижается по правилам ADR-0004, интервал сбрасывается до 1 дня, тема попадает в рекомендации.
- **Повторение** — короткий квиз из 3 вопросов по теме из пула (вопросы темы + практика), по возможности не те, что были в прошлый раз.
- Экран **«Повторить сегодня»**, счётчик в шапке, просроченные повторения в рекомендациях (обнови чистую функцию рекомендаций и её тесты).
- Логика интервалов — **чистая функция с unit-тестами** (граничные случаи: повтор раньше срока, сильно просроченный повтор, провал на каждом шаге).
- **Демо:** у демо-учеников в сиде есть история с датами в прошлом (например, Фарзона освоила Variables 3 дня назад, и повторение уже ждёт). История создаётся через реальный код скоринга (ADR-0006). Машину времени в UI не делай; если нужна для репетиций, только через dev-флаг, отключённый по умолчанию.

#### A4. Итоговый проект и портфолио (FR-PROJ, Should)
- У предмета есть **итоговый проект**, использующий все 6 тем. Например: «Программа учёта оценок класса: ввод оценок, среднее, максимум, поиск ученика». Описание и критерии оценки на tg/ru/en.
- Ученик сдаёт **ссылку** (только `https://`, GitHub / Gist / Replit) и короткое описание. Учитель в панели класса (B2) принимает или возвращает на доработку с комментарием.
- **Публичное портфолио** по неугадываемой ссылке `/p/[code]`: освоенные темы, рост (A1), сертификат (A5), принятый проект. Показываются только имя и учебные результаты. Ученик может выключить публичную ссылку.

#### A5. Сертификат с проверяемой ссылкой (FR-CERT, Must)
- Выдаётся, когда **все 6 тем `MASTERED`** и **итоговый тест ≥ 80%**. Если принят итоговый проект, сертификат получает отметку «с проектом». Правило выдачи — чистая функция с тестами.
- Перед выдачей гость вводит **имя для сертификата**. В сертификат сохраняется снимок: имя, предмет, дата, баллы до и после.
- У сертификата **неугадываемый код** (например, `NV-XXXX-XXXX` из криптостойкого генератора) и публичная страница **`/verify/[code]`** без сессии: «Действителен / Отозван», имя, предмет, дата, результаты. Несуществующий код даёт понятный ответ «не найден» без утечки информации.
- **Печатная версия** через print CSS (браузер сохраняет в PDF), в фирменном стиле (`BRAND_GUIDELINES.md`), на всех трёх языках. QR-код на `/verify` — только если владелец одобрит библиотеку; иначе крупная короткая ссылка.

### B. Деньги (ответ на вопрос 3)

Реальных платежей **нет и не будет** до защиты. Мы показываем модель и проверяем спрос.

#### B1. Тарифы и проверка спроса (FR-PLAN, Must)
- Страница **`/pricing`** с четырьмя колонками:
  - **Бесплатно:** все уроки, квизы тем, входной тест, практика, повторения, серия дней.
  - **Pro (подписка):** итоговый тест, сертификат, портфолио, расширенная практика, безлимитные повторения. (Окончательный состав предложи сам и обоснуй.)
  - **Для школ и учебных центров (B2B):** панель класса, отчёты, проверка проектов, экспорт. Оплата за класс или ученика.
  - **Для авторов (маркетплейс, скоро):** преподаватели публикуют курсы, платформа берёт комиссию.
- Цены — **заглушки с пометкой «предварительно»** из конфига. Владелец заменит их после разговоров с 2–3 учебными центрами. Никаких выдуманных цифр в коде.
- **Формы заявок** «Подключить школу / центр» и «Стать автором». Сохраняются в БД (организация, имя, контакт, сообщение), валидация Zod, защита от спама на уровне MVP. Количество заявок — живой сигнал спроса на защите.
- **Права доступа** — одна центральная функция `entitlements(user)` (с тестами), а не проверки, разбросанные по коду. Метки «Pro» в UI. Для демо: демо-ученики Pro, гость Free с кнопкой «Попробовать Pro (демо)», чтобы показать, как работает ограничение.

#### B2. Панель учителя «Мой класс» — ядро B2B (FR-CLASS, Must)
- Сущности `Class` и `Enrollment` (уже набросаны в `data-model.md` → Later entities), учитель. Роль учителя предложи сам: новый `UserKind` или отдельная роль. Учитель в MVP — **демо-профиль** (например, «Учитель Мадина»), без паролей, как ADR-0006.
- **Вход в класс по коду:** ученик (гость или демо) вводит код класса.
- Панель:
  - тепловая карта **ученики × темы** по статусам mastery;
  - **топ-3 слабых темы класса** с подсказкой, что разобрать на уроке;
  - средний рост «входной → итоговый» по классу;
  - кто просрочил повторения;
  - очередь проверки итоговых проектов (A4);
  - экспорт CSV.
- **Изоляция:** учитель видит **только свой класс**; ученик не видит других учеников, кроме рейтинга (C4). API-тесты на изоляцию между классами и учениками обязательны.
- Сид: демо-класс «9А» из 6–8 демо-учеников с разной историей (через реальный код скоринга), чтобы панель выглядела живой.

#### B3. Маркетплейс авторов (Could, только витрина)
- Не строим. Колонка в `/pricing`, форма «Стать автором», раздел в `business-model.md` и в роадмапе после защиты.

### C. Привлечение людей (ответ на вопрос 4)

#### C1. Главная под нишу (Must)
- Заголовок и подзаголовок про подготовку по информатике на родном языке, главный CTA **«Проверь свой уровень за 5 минут — без регистрации»** ведёт на входной тест. Второй CTA «Для учителей и центров» ведёт на `/pricing#schools`.
- Визуальный контракт `VISUAL_EXPERIENCE.md` (luminous knowledge core, без шаблонной сетки карточек) сохраняется. Меняется смысл, а не идентичность.

#### C2. Бесплатный инструмент-вход + карточка результата (Should)
- Входной тест (A1) и есть бесплатный инструмент.
- После теста **карточка результата** для шаринга: страница `/share/[code]` с OG-картинкой через встроенный в Next.js `ImageResponse` (без новых зависимостей): «Мой уровень по информатике: 62%. Проверь свой». Кнопка «Поделиться в Telegram» через обычную ссылку `https://t.me/share/url?...`, без API.
- В карточке нет персональных данных, кроме имени, если ученик сам его указал.

#### C3. Telegram-канал (Should)
- Ссылка на канал (из env-конфига, например `NEXT_PUBLIC_TELEGRAM_CHANNEL_URL`; если не задано, ссылка скрыта) в подвале, после результатов и в отчёте роста.
- Контент-план канала (короткие уроки и задачи дня, ведущие на сайт) — в `go-to-market.md`.
- Бот-напоминалка о повторениях — **после защиты**, в роадмап.

#### C4. Геймификация (Must: серия дней; Should: XP и рейтинг)
- **Серия дней:** день засчитывается при любой учебной активности (урок, квиз, практика, повторение). Часовой пояс по умолчанию Asia/Dushanbe. Показ в шапке и на прогрессе. Чистая функция с тестами (смена дня, пропуск, часовой пояс).
- **XP** за действия (урок, пройденный квиз, практика, повторение в срок). Таблицу начислений вынеси в конфиг и задокументируй.
- **Недельный рейтинг класса** (только внутри класса B2, только имена). Глобального рейтинга нет.

#### C5. Рефералы (Could)
- Личная ссылка-приглашение `?ref=код`. Когда приглашённый проходит входной тест, пригласивший получает бонус (например, XP или 7 дней Pro-практики в демо). Простая защита от самоприглашения (тот же пользователь или cookie).

#### C6. Партнёрство с учебным центром (документ)
- План пилота с нашим учебным центром или вузом в `go-to-market.md`: кому предложить, что дать бесплатно, что измерить.

### D. Измерение эффекта и пилот на живых людях (Must)

- Страница **«Эффект»** (`/impact` или раздел `/status`) с **агрегированными анонимными** метриками:
  - число учеников, прошедших входной тест;
  - средний балл «входной → итоговый» и средняя дельта;
  - процент успешных повторений на 1/3/7 день;
  - число выданных сертификатов;
  - заявки от школ и авторов.
- **Демо-пользователи исключаются** из метрик (флаг «показывать демо-данные» допустим, но по умолчанию выключен). Иначе цифры на защите будут нечестными.
- **Пилот до понедельника:** 5–10 реальных людей (одногруппники, школьники) проходят «входной тест → уроки → практика → итоговый тест». Подготовь в `docs/06-quality/pilot-plan.md` сценарий, что говорить участникам, согласие на анонимное использование результатов и как отделить пилотные данные от демо.
- Как дать пилоту доступ (тот же ноутбук, локальная сеть или временный хостинг) — **решение владельца**. Перечисли варианты с плюсами, минусами и рисками безопасности (ADR-0006: демо-профили недопустимы при публичном доступе). Сам ничего не разворачивай.

## 3. Новый сценарий демо (обнови `mvp-scope.md`)

1. Главная (ru): ниша и CTA «Проверь уровень за 5 минут». Проходим **входной тест как гость** → карта знаний сразу заполнена → карточка результата → «Поделиться в Telegram».
2. Переключаемся на **Фарзону** (tg): серия дней, **«Повторить сегодня: Переменные»** → проходим повторение → следующий интервал 3 дня.
3. Тема **Циклы**: урок → **практика с вводом ответа** → квиз 50% → рекомендации (сначала Условия как пререквизит).
4. **Рустам** (почти всё освоено): **итоговый тест** → **«Твой рост: 38% → 86%»** → **сертификат** → открываем **`/verify/[code]`** в новой вкладке (как работодатель) → публичное портфолио с проектом.
5. **Учитель Мадина**: класс 9А, тепловая карта, топ-3 слабые темы, проверка проекта, экспорт CSV.
6. **`/pricing`**: Free / Pro / Школы / Авторы, оставленные заявки.
7. **«Эффект»**: реальные цифры пилота (без демо-данных).
8. Переключение en и тёмной темы на любом из экранов.

Цифры в сценарии (38% → 86% и т. п.) — примеры. Реальные значения берутся из сида и пилота.

## 4. Нефункциональные требования (для всего нового)

- **Безопасность:** правильные ответы (`isCorrect`, допустимые short-answer) не уходят клиенту до отправки. `/me/*` только из сессии. Учитель видит только свой класс. Публичные страницы (`/verify`, `/p`, `/share`) показывают минимум данных, коды неугадываемые, есть индекс по коду. Внешние ссылки проектов только `https`, `rel="noopener noreferrer"`. Формы заявок валидируются Zod. Новые секреты только через `.env.example` (сам `.env` не трогаешь).
- **Тесты:** unit-тесты на скоринг SHORT_ANSWER, интервалы повторения, выдачу сертификата, серию дней, XP, `entitlements`, рекомендации с повторениями. API-тесты на изоляцию классов и учеников, на `/verify`, на отсутствие утечки ответов. Обнови `seed:check` и счётчики в seed-тестах осознанно.
- **UI (Definition of Done):** светлая и тёмная тема, tg / ru / en без захардкоженных строк (тест паритета ключей проходит), от 360 px, клавиатура, состояния загрузки, пустые и ошибки переведены, reduced motion. Текущий цикл обучения не ломается.
- **История учеников не стирается** (D-21): миграции только добавляют, политика удаления соблюдается, новые FK на контент из истории — `RESTRICT`.
- **Зависимости:** по умолчанию без новых. Каждую предложенную (Pyodide, QR и т. п.) спрашивай отдельно, с размером и альтернативой.
